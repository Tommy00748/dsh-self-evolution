# 中文说明（README.zh-CN.md）

> 英文主 README 在 [`README.md`](README.md)。这里给中文使用者一份**更短**的快速上手说明，完整设计细节（信任边界、每条配置项、验证记录）以英文版为准。

**给 DeepSeek Harness（DSH）补上"会自己成长"的那一层**：长期记忆、每轮结束后的自动复盘、技能沉淀与自动合并、技能健康检查、跨会话召回，以及输入框上方那张"刚学会了什么"的小卡片。

设计移植自 Nous Research 的 [Hermes Agent](https://github.com/NousResearch/hermes-agent) 自改进循环，**不改 DSH 内核**；记忆文件格式与 Hermes 完全一致，两边可以互换。

## 它提供什么

| 能力 | 一句话说明 |
|---|---|
| **`memory` 工具** | 长期记忆，写进 `~/.dsh/self-evolution/MEMORY.md` 和 `USER.md`。有上限（默认 2200 / 1375 字符），满了会让模型自己合并；写入前扫一遍危险内容（隐藏字符、越权指令、密钥外泄等）。 |
| **`skill_learn` 工具** | 把刚走通的流程写成技能文件。写完会立刻回读复检，**加载不了就回滚**，绝不报告一个其实用不了的技能。 |
| **`skill_doctor` 工具** | DSH 对格式坏掉的技能是**静默丢弃、零告警**的。这个工具把 DSH 会读的每个技能目录扫一遍，报告哪些会被丢掉、为什么，并可选地把引号这类问题**外科式修好**（先备份）。 |
| **后台自动复盘** | 每轮对话结束后自动调一次便宜模型，判断这轮有没有值得留下的东西。中断或报错的轮次永不学习；任何失败都被吞掉，不会影响你的会话。 |
| **技能不堆积** | 同类事情会**合并进已有技能并压缩**，不会堆出几十个雷同技能；改写前自动备份，超长就拒写。 |
| **`session_search` 工具** | 搜你自己过去所有会话的**真实消息**。用法要点：**一次只搜一个特征词**——多个词会被当成一个完整短语，越搜越窄。 |
| **`evolution_log` 工具** | 自动复盘是"偷偷"发生的，所以必须能查：按时间倒序列出每次学了什么、以及模型给出的理由。 |
| **界面卡片** | 平时不占地方（只在统计行留一个很淡的 `◈`）；**学到新东西或有事等你确认时自己冒出来**，读完自己收走。 |

## 为什么敢开着用

1. **写坏了不会丢**：每次写入都回读复检，加载不了就回滚。
2. **不会偷偷改你的记忆**：无人看管的复盘**只能新增**；想删或想改，必须先问你，并且把**要动的那段原文全文**摆出来给你看——原文在你排队时就被"钉住"，事后那条变了就作废，绝不会改到别的条目上。
3. **能分清"谁写的"**：它自己记的条目带一个 `自动` 小标记，你让它记的没有。
4. **它唯一的写接口只认本机 + JSON 请求**，别的网页发不出这种请求。

## 安装

```bash
dsh plugin --profile <你的 profile> add dsh-self-evolution
```

再把这一行挂进 profile 补丁层（`~/.dsh/profiles/<profile>/cordis.patch.yml`）：

```yaml
- id: self-evolution
  name: 'dsh-self-evolution'
  config:
    memoryCharLimit: 2200
    userCharLimit: 1375
```

**宿主那一半**（工具、提示词注入、网页接口）下次启动 DSH 才生效；**界面那一半**（`client.js`）会自己热更新，改完约 1 秒就在运行中的窗口里生效，不用重启、也不用刷新页面。

卸载时把 `dsh.profile.bundles` 里的包名去掉、删掉包目录即可。**你的记忆和技能文件不会被删除**。

## 已知限制（挑几条要紧的）

- 卡片里的学习记录**只能看，不能改**（Hermes 的 `/journey` 能编辑，我们还没做）。
- `session_search` 用的是 SQLite 的分词器：**按词匹配，不是任意子串**（搜 `AI` 不会命中 `BRAID`）；中文只认被空格或标点隔开的**整词**。
- 记忆是**全局共享**的（跨会话），不是按项目隔离；要隔离就把 `storeDir` 指到工作区里。
- 插件在宿主进程里用 `node:fs` 写文件，**它的写不受会话文件沙箱约束**——默认路径只有两处，都可在配置里改。详见英文 README 的 Trust boundary 一节。

## 测试

```bash
npm test                 # 宿主 + 界面两半
node test/host.test.mjs  # 宿主：假上下文真跑 apply()，155 项检查
node test/client.test.mjs# 界面：核对样式类名、动画名、中英文案三者对得上
```

界面那一半是浏览器模块，出错时**外面看不出来**（模块照样加载、卡片照样显示）。所以 `client.test.mjs` 会把真正的 `client.js` 跑一遍再交叉核对：渲染用到的每个类名都有样式、每个动画名都有定义、每句文案中英文都在。这不是形式主义——曾经有一次人工改大段字符串，**悄悄删掉 18 条样式规则和一条文案**，而语法检查照样通过、界面看着也正常，只有细看才发现面板里的字全退回了默认样式。
